# 公众号发布清单

面向微信公众号的发布准备。每篇给出**标题**(带 pstack 和系列号)、**摘要**(标题下那句话)、以及**开头钩子**(正文第一段,直接可用)。

## 发布前注意

- **外链不可点。** 公众号正文里的外链打不开,所以每篇文末的「参考」已经改成纯文本:仓库地址 `github.com/backnotprop/pstack` 加各文件的相对路径。读者可自行到仓库检索。
- **第 15 篇有两张 mermaid 流程图**,公众号不渲染,需要先导出成图片再贴。
- **表格**在公众号编辑器里通常要重建,建议截图或重排成列表。
- **反引号里的标识符**(如 `poteto-mode`、`principle-prove-it-works`)会保留,保持原样即可,它们是这套系统的接口名。
- 系列名字统一用 **pstack 拆解**。

## 开头钩子

每篇正文已经以具体场景开场(网站版和公众号版一致),下面列出第一段,可以直接用,也可以作为选题依据。

| # | 开头 |
|---|---|
| 01 | 你让 agent 给一个命令加一个 `--json` 开关。它新建了一个 `JsonFormatter` 类、一个 `Formatter` 接口、一个工厂函数,把 `format` 参数穿过六个函数,顺手加了一个配置项。diff 有 400 行。评审花掉一个小时。两周后,有人发现文本输出被改坏了。 |
| 02 | 你把旧 API 手工迁到新 API。三百个文件,改了两天。合并上游改动时冲突了一轮,又重改一遍。改动本身没错,错在它是手工做的,而手工做的改动只能靠手工复核。 |
| 03 | 系统里有一条规则:订单一旦发货,就不能再改收货地址。这条规则没有写在任何一个地方。它是七个 `if` 加起来的样子。 |
| 04 | agent 报告完成了。CI 是绿的。你手动点了一下,功能是坏的。 |
| 05 | 你手上同时开着三个 agent。一个在改 bug,一个在补测试,一个在迁移一个老模块。半小时后你回来,发现三个都卡在同一件事上:等你点一下许可。 |
| 06 | 你让 agent 改一段你不熟的代码。它很快改完了,而且第一眼看起来还挺合理。两周后你才发现,它修的是症状不是原因。 |
| 07 | 一次尝试,会锁死模型想到的第一个形状。 |
| 08 | 你问 agent 验证过了吗,它说验证过了。你再问怎么验证的,它说跑了一遍测试。 |
| 09 | 代码写完不等于可以交付。这一组四个 skill 管的是产物读起来像不像人做的。 |
| 10 | 这一组九个 skill 是系统的外围器官。它们不直接干活,它们让系统自己变好、自己可审计、自己可配置、自己可被引导。 |
| 11 | 一个 agent 报了个 bug,顺手就开始改。改到一半你才发现,它连问题的成因都判断错了。 |
| 12 | 你让 agent 加个功能。它写得很快,测试也过了,两周后你却发现它从一开始就抓错了数据形状。 |
| 13 | 你的栈全绿了。CI 绿,一个 bot approve,你点了 merge。第二天发现其中一个 PR 其实从没被真正验证过,而它底下还压着三个。 |
| 14 | 昨天你让 agent 做了一半的活。今天换了个会话,你说"接着做"。它从零开始,把昨天已经做完的部分又做了一遍。 |
| 15 | 你敲了一句话,没有指定任何 skill。然后 todo list 自动长出了十几条步骤,最后交回一段带证据的回复。 |
| 16 | 这套东西不是免费的,也不是到处都该用。 |
